# HelpTeacher — Платформа автоматизации учебного процесса

Современная модульная веб-платформа для комплексной организации учебного процесса в вузе: ведение электронного журнала, управление лабораторными работами и очередями на сдачу, автоматический расчёт аттестации, гибкое расписание занятий и многофакторная безопасность.

---

## 🚀 Ключевые возможности

### 👥 Ролевая модель доступа
- **Студент (`STUDENT`):** личный кабинет, просмотр индивидуального и группового расписания, отслеживание дедлайнов, сдача решений лабораторных работ в очередь на проверку, прозрачный мониторинг баллов аттестации.
- **Преподаватель (`TEACHER`):** ведение журнала посещаемости и оценок, публикация лабораторных работ и материалов, управление продлениями дедлайнов (extensions), приём защит по электронной очереди, выгрузка отчётов (CSV/XLSX).
- **Администратор (`ADMIN`):** системный аудит действий пользователей, управление бэкапами (MinIO/S3), мониторинг безопасности (rate-limiting, блокировка подозрительных сессий, fingerprint-валидация), impersonation-режим для оперативной поддержки.

---

### 📦 Продуктовые модули

| Модуль | Описание функционала |
| :--- | :--- |
| **Электронный журнал** | Учёт занятий, статусы посещаемости (`present`, `absent`, `late`, `excused`), баллы (`0–100`), пакетное выставление и фильтрация по подгруппам. |
| **Лабораторные работы** | Жизненный цикл заданий (`draft → published → archived`), персональные и групповые дедлайны, прикрепление файлов решений в S3, электронная очередь на очную защиту. |
| **Автоматическая аттестация** | Расчёт итогового рейтинга по гибкой формуле: `score = labs·w1 + attendance·w2 + activity·w3 + manual·w4` с поддержкой динамической автобалансировки весов (`autobalance`). |
| **Интеллектуальное расписание** | Парсинг и структурирование академических слотов, группировка потоковых лекций, индикация заполненности посещаемости с учётом часового пояса МСК. |
| **Безопасность и сессии** | Двухфакторная авторизация (JWT access/refresh), привязка сессий к физическим устройствам через Device Fingerprinting (`ThumbmarkJS`), защита от брутфорса и CSRF, аудит-лог. |
| **Интеграции** | Оповещения и связывание аккаунтов через **Telegram Bot** (webhook) и **VK Bot** (long polling). |

## 🛠 Технологический стек

### Backend
- **Язык & Фреймворк:** Python 3.11+, **FastAPI** (асинхронная архитектура)
- **База данных & ORM:** **PostgreSQL 16**, **SQLAlchemy 2.0** (async-first сессии), **Alembic** (миграции)
- **Валидация данных:** **Pydantic v2**, Pydantic Settings
- **Фоновые очереди & Кэширование:** **Celery 5.4**, **Redis 7.2**
- **Объектное хранилище:** **MinIO** (S3-совместимое хранилище файлов решений и бэкапов)
- **Боты & Вебхуки:** **aiogram 3.26**, **vk_api**

### Frontend
- **Фреймворк:** **Next.js 16** (App Router), **React 19**, **TypeScript 5**
- **Стилизация & UI:** **Tailwind CSS 4**, **Radix UI** (доступные примитивы компонентов), Lucide Icons, Tabler Icons, Framer Motion
- **Управление состоянием & Формы:** **Zustand**, **React Hook Form**, **Zod**
- **Редактор контента:** **Lexical Editor** с поддержкой KaTeX (математические формулы)
- **Безопасность клиента:** **ThumbmarkJS** (аппаратный фингерпринт браузера)

### DevOps & Тестирование
- **Инфраструктура:** Docker Compose (multi-container dev stack), Nginx reverse proxy
- **CI/CD:** GitHub Actions (автоматический typecheck, линтинг, запуск тестов, деплой на VPS)
- **Тестирование:**
  - Backend: `pytest`, `pytest-asyncio`, `hypothesis` (property-based testing)
  - Frontend: `Vitest`, `@playwright/test` (E2E smoke- и regression-тесты)
  - Линтеры: `ruff` (линтер и форматтер), `mypy` (статический анализ типов)

## ⚙️ Быстрый старт

### Требования
- Docker & Docker Compose
- Node.js 20+ (для локальной разработки фронтенда вне контейнера)
- Python 3.11+ (для локального окружения бэкенда)

### Запуск полного стека через Docker Compose

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/pradigmaz/platform_help_teacher.git
   cd platform_help_teacher
   ```

2. Подготовьте переменные окружения:
   ```bash
   cp deploy/.env.dev.example deploy/.env.dev
   ```

3. Запустите инфраструктуру:
   ```bash
   docker compose -f deploy/docker-compose.dev.yml --env-file deploy/.env.dev up -d --build
   ```

После запуска сервисы доступны по адресам:
- **Frontend:** `http://localhost:3000`
- **FastAPI Docs (Swagger UI):** `http://localhost:8000/docs`
- **MinIO Console:** `http://localhost:9001`
